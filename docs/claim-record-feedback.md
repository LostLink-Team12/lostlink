# 报告认领关联与记录展示规则

## 失物报告的已认领标记

从失物报告匹配结果或通知邮件入口提交认领时，前端携带 `lost_report_id`。Claim Service 在创建认领的同一数据库事务中持久化此来源，因此刷新页面、换设备或重新登录后仍能显示“Claim submitted”。普通搜索发起的认领不关联报告；未提交成功时不产生标记。

报告保持原有 open / closed 状态。“已发起认领”是历史标记，不等于申请已经批准或物品已经找回，不会自动关闭报告。拒绝或撤回申请不会清除历史标记，页面同时展示最新关联申请的当前状态。找到物品后仍由失主手动关闭报告。

关联 ID 是来源元数据，不是访问凭证。Claim Service 不跨服务查询或授予报告权限，也没有跨服务外键。列表按当前登录者和来源报告共同过滤，即使有人自行填写其它报告 ID，也不能在报告所属用户的页面写入标记或读取对方的认领。报告页面只为当前页的报告读取最新一条自身关联申请。

## 部署与协作

Claim 数据库需执行 Alembic 到 `0002_claim_report`，新增可空列及部分索引，既有申请保留空来源，不推断历史关联。无需新增 AWS 权限或消息订阅；本改动不改变 Matching、Claim 的服务边界。部署负责人应先执行迁移再启动新 Claim API/worker。

## 认领详情的原位展开

Owner 的 View claim 与 Venue 的 Review claim 共用同一列表组件：选中后原卡片变为浅绿色并在原位置加载答案及操作；一次仅展开一条，支持 Hide details 收起。加载错误、撤回进度和操作反馈均属于被点击的卡片，不在分页器前追加新的详情卡片。列表刷新保留未完成异步操作的详情状态。

## 时间戳

- Venue Found items：Found（拾获时间）及 Registered（登记时间）。Item API 从已有数据库列补充返回 created_at，不新增数据列。
- Owner My lost reports：Reported（报告创建时间）。
- 两端认领列表和展开详情：Submitted（申请创建时间），以及存在时的 Approved 和 Closed 时间。收起卡片也可直接看见。
- 时间按浏览器本地时区显示并附时区名称；HTML time 的 datetime 与提示保留 UTC。后端未提供或格式无效的时间不显示，绝不以当前时间代替历史时间。
