# 失物报告匹配与焦点体验修复

## 关闭后的匹配入口

报告关闭后禁用 View matches，并说明已停止匹配。关闭当前正在查看的报告时立即收起结果，不等待列表刷新完成；服务器确认关闭后，本地同步状态，避免慢网络下再次打开。刷新报告列表时清除旧结果，防止显示已经过时的匹配。

## 报告浏览与自动匹配分离

原报告结果来自自动匹配记录，使用通知阈值；Search 的交互检索默认最低相似度为 0，因此结果数量本来不同。报告的 View matches 现在调用 `/v1/lost-reports/{id}/candidates`，用保存的向量、模型版本与过滤条件进行同规则交互检索。原 `/matches`、后台阈值、match.found 事件及邮件通知语义保持不变，不通过降低通知门槛增加误报。

新增接口仅允许报告所属失主读取，关闭报告不返回候选。最多检索既有 candidate_limit（上限 100）个候选，每页 20 条，按实时可用且版本有效的结果分页，多读取一条有效结果判断下一页。窗口耗尽时明确显示限制；不会声称穷尽整个库存。更换报告会重置分页，请求进行中禁用翻页；禁用分页按钮统一显示不可用鼠标；加载状态通过文字和 aria-busy 表达，不再改变为转圈鼠标。报告列表与相似物品列表有独立分页名称及已显示的范围。

不新增数据库迁移，避免触发此前部署的迁移基线流程。

## 程序焦点与键盘操作

登录进入页面和切换页面时仍把焦点放到标题，方便屏幕阅读器定位；标题、认领标题和静态详情容器使用专门样式，不显示交互控件的橙色框。按钮、链接、输入框及其它交互控件的 focus-visible 样式保留，没有全局移除键盘焦点提示。

## 验证

- 前端完整测试 106 项通过；Matching 非集成、非模型测试 62 项通过；TypeScript 与生产构建、全库 Ruff、格式检查及 OpenAPI 同步检查通过。
- 本地浏览器用 25 条模拟候选验证第一页 20 条、第二页 5 条，下一页/上一页随实际数据启用；禁用按钮的鼠标为 not-allowed，390 像素手机页面无横向溢出。
- 浏览器确认自动聚焦标题的 outline 为 none，按 Tab 后输入框仍有可见 solid 焦点提示。
- 新增 PostgreSQL 集成测试验证保存查询与 Search 的候选顺序一致、分页、归属隔离、关闭后为空且交互浏览不写入自动匹配记录。真实数据库部分交由 CI 执行；本轮不触发云端发布。

## 其它列表的统一检查

Owner 的报告/认领，以及 Venue 的库存、审批、员工列表都使用同一 PageList。分页栏和被锁定侧栏统一使用 not-allowed 鼠标；加载状态通过文字、禁用状态与 aria-busy 反馈。每个列表具有独立的分页名称。

补充修复：请求下一页期间仍显示当前已加载页的页码和范围，不给旧数据贴上下一页编号；请求失败后保持当前页，再点 Next 或 Retry 不会跳页。首次加载失败也可在列表内重试。补充五类页面各 25 条记录的前进/后退验证。
