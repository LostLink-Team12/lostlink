# Owner App 三项后续修复

本轮沿用 `codex/owner-app-fixes`，按图片恢复、权限展示、日期校验顺序，各自独立提交。
不创建 PR、不推送、不部署。首次实测现象保留在 `2026-10-23-owner-app-fixes.md`。

## 1. 过期图片恢复

新增 `GET /v1/items/{item_id}/photo`（Matching 公共 API，需要允许的用户客户端和 owner 身份）。
它复用现有机器身份向 Item 查询权威状态；仅当物品仍为 available 且存在照片时返回短期签名 URL。
响应 `Cache-Control: no-store`，只包含 item_id、photo_url，不泄露存储 key、租户上下文或私有答案。
物品被预留、交接、删除或 Item 不可用时，按原错误模型拒绝；不执行新的 CLIP 推理，不扩大 IAM 权限。

搜索结果、报告匹配和通知匹配使用相同图片组件。首次加载失败自动刷新一次链接；恢复后仍加载失败，
或接口返回不可见/不可用时，显示占位和显式重试按钮，不无限循环。并发错误只发一个刷新请求；
新查询替换卡片后，丢弃旧请求结果。原来的 120 秒签名有效期及私有 bucket 设置不变。

验证：前端 35 项测试、生产构建通过；Matching 单元测试 54 passed（16 项集成/模型用例未运行）。
回归覆盖鉴权、非 available 状态、依赖失败、过期恢复、重试次数、并发错误及卡片替换。
新接口需要与前端一起部署；本地测试使用隔离的 SDK/API 替身，未访问 AWS、未更新线上服务。


## 2. 场馆界面按当前能力展示

新增 Venue `GET /v1/session`，仅接受允许的人类应用及有效 Cognito access token。
普通 Owner 不查询其他场馆、不返回员工或平台能力；有场馆角色的用户复用现有 employee 校验，
核对当前成员状态、实际角色与场馆状态。旧管理员 token 不会绕过降权/停用；能力不从浏览器自行解码 token 得出。
平台入驻另外要求 platform 客户端及 platform_admin 身份，不需要事先拥有场馆。
响应只含当前场馆公开资料和三项能力，禁止缓存；数据库不可用时不推断授予权限。

前端先完成能力查询再加载场馆数据；普通 Owner 看到无权限说明、返回 Owner App 链接和重新检查入口。
员工可登记/查看物品和审阅认领，管理员额外看到员工管理，平台管理员额外看到入驻表单。
平台管理员没有场馆时仍能入驻，操作反馈独立显示；刷新可重新检查撤权，查询失败可重试。
所有后端业务接口仍执行原有独立鉴权，不将能力展示当作授权凭证，不修改用户角色或 IAM。

验证：前端 42 项测试、生产构建通过；Venue 27 项单元测试通过（29 项集成用例未运行）。
覆盖初始等待、拒绝时不请求场馆数据、角色矩阵、查询失败、刷新撤权、过期管理员角色、停用成员与场馆、平台客户端边界。


## 3. 日期区间校验与可读错误

搜索和保存报告共用 FoundDateFilters：输入旁立即显示区间错误，日期控件通过 aria-invalid 与
aria-describedby 关联提示。提交无效区间会展开筛选器并聚焦日期输入，不发送搜索、保存或图片编码请求。
修正日期后自动清除提示；允许无界、单边和相等的时间边界，并按原语义转换本地时间为 UTC。

Matching 的共享 Filters 将倒置区间标记为稳定类型 `invalid_date_range`，继续使用原有
422 错误 envelope 与已清洗的 details，不返回搜索内容或输入值。
API 客户端将该类型及 found_from/found_until 字段错误转换为可读英文，保留其他业务错误原样。
这不改变错误响应结构、数据库或事件契约，不需要迁移。

验证：最终前端 47 项测试、Matching 56 项单元测试、Venue 27 项单元测试通过；
生产构建、OpenAPI 契约一致性、Ruff 检查通过。覆盖两个提交按钮、折叠筛选器的错误定位、
修改后恢复提交、时间边界与 UTC、服务端 422 类型和隐私保护。
现有网关允许受保护的 `/api/<service>/v1/` 路径，新接口无需开放 internal 路由。

## 交接与上线

三项均在本地分支独立提交，未创建 PR、未推送、未部署。Matching、Venue 和前端需要协调发布：
先让两个服务支持新接口，再发布使用它们的前端；当前自动 CD 会从同一源码 SHA 更新相关服务和前端，
滚动过程中旧版本服务可能暂时返回 404，前端会保留占位/访问失败说明和手动重试，避免显示未核实的操作。
不回退到解码 JWT 自行授权，也不改变 S3 的私有性或签名有效期。

本轮未使用真实 AWS 部署身份、未修改账号权限、未新增业务记录。验证以离线 TestClient 与前端
组件测试为主；新接口尚未在线上部署，不将上轮真实登录检查作为本轮新接口的线上验收。
